# SQL Assistant Request Flow Note

This note captures the current architecture before the reliability changes in this pass.

## Main Flow

1. The React frontend keeps a `session_id` in localStorage and sends it with `/upload`, `/chat`, `/clear`, and MySQL attach calls.
2. `backend/main.py` owns the API surface. `/chat` resolves the current session source and dispatches to:
   - `chat_pipeline.ask_mysql(...)` for live MySQL databases.
   - `chat_pipeline.ask_sqlserver(...)` for SQL Server sources.
   - `chat_pipeline.ask(...)` for SQLite files.
3. MySQL chat first builds a deterministic semantic query plan with `semantic_parser`, then uses `question_classifier`, `business_catalog`, `database_memory`, `entity_resolver`, and `relationship_discovery` before calling the LLM.
4. SQL is generated by `llm.generate_mysql_sql`, validated by `mysql_adapter.validate_sql`, executed through the MySQL adapter, then summarized by `llm.generate_answer` with a local fallback formatter.
5. Redis caches final `/chat` responses only. Cache identity includes database/schema identity, provider/model, question classification, resolver metadata, relationship/catalog versions, prompt version, and result shaping version.
6. MCP tools in `backend/mcp_server.py` are LLM-free and expose schema inspection, entity resolution, SQL validation, dry runs, and read-only execution for SQLite/MySQL/SQL Server.

## Existing Protections

- Session state is scoped per `session_id`.
- MySQL, SQLite, and SQL Server have separate validators/executors.
- Query execution is read-only and limited.
- Frontend hides token/cost metrics and shows confidence instead.
- Entity resolver avoids treating common metric words such as `highest purchase value` as named entities.
- Semantic parsing separates operation, metrics, dimensions, aggregation/sort/limit/date/status constraints, requested output, and candidate entity mentions before entity lookup.

## Remaining Risk Area Addressed Here

- MySQL prompts previously used either very broad full schema or narrow selected schema. This pass adds a focused mode: compact database-wide table index plus detailed candidate tables.
- Entity-scoped relationship questions could return zero rows after choosing the wrong path. This pass adds a generic empty-result repair path that keeps resolved entities anchored and asks for an alternate validated join path.
- Cache versions are bumped so old wrong answers do not survive resolver/prompt/result changes.
